# 无 RAG 报告、规则校验与最小局部修复

## 目标

完整报告只依赖确定性排盘上下文与 DeepSeek 的统一分析，不再检索或注入 RAG 资料。程序不试图裁决身强、格局、喜用等流派判断，但会保护可以机械判断的基础事实。

## 主流程

```text
确定性排盘
  ↓
紧凑只读 Context（原局 + 起运 + 全部大运）
  ↓
DeepSeek 单次整体流式分析
  ↓
Schema 与程序规则校验
  ↓
可直接修复项 / 受限 JSON Patch 局部修复
  ↓
程序生成 Reflection
  ↓
正式报告
```

主输入不包含检索计划、检索结果、证据正文或引用白名单。报告契约中的 `evidence_ids` 仅为旧接口兼容字段，模型必须输出空数组，正式报告的 `evidence` 也固定为空。

## 紧凑 Context

完整命理层级不会被裁掉：

- 原局四柱、十神、藏干、五行、月令、人元司令、神煞和原局关系；
- 起运方向与起运时间；
- 全部大运的起止年份/年龄、干支十神、藏干、十二长生、自坐、旬空、纳音、紧凑神煞以及与原局的确定性关系；
- 已预计算的流年、流月、流日资料（存在时）；
- 稳定 `fact_id` 目录。

删除的是重复副本、来源定位、规则版本、嵌套参与者对象、空值和审计元数据。完整原始命盘仍由数据库与调用轨迹保留。

## 程序规则校验

当前硬校验只覆盖可确定事实：

- 日主与天干的十神映射；
- 地支藏干；
- 五行相生相克方向；
- 基础冲、合、刑、害、破关系；
- 命盘、学校和引用的 `fact_id` 一致性；
- 出生至起运及全部大运阶段覆盖；
- 明确绝对化高风险断言。

身强弱、格局、调候与喜用仍由模型综合解释，程序只要求它们不违反确定性事实。Reflection 由校验结果生成；模型自评不再作为通过闸门。Reflection 中引用的旧错误诊断不会再次作为报告正文回扫。

## 最小局部修复

校验错误先映射到最小可替换 JSON 单元，例如一条 claim、一个六亲对象、一个健康维度或一步大运。修复请求只包含：

1. `allowed_paths`；
2. 当前错误块；
3. 机器可读错误与期望值；
4. 冻结的全局结构结论；
5. 少量一致性相邻块；
6. 按错误类型投影的相关原局/岁运事实。

模型只能返回 `analysis-json-patch-v2`，操作仅允许 `replace` 或 `remove`，且路径必须位于 `allowed_paths`。未授权章节不会被改写。无法定位的跨章节根本性错误才回退为完整修订。

## 日志

每次主调用和每次修复调用都在 `generation_trace.attempts` 中保存：

- 实际 system prompt；
- 完整输入 payload；
- 本次 JSON Schema；
- 模型原始结构化返回；
- provider reasoning（若接口返回）；
- token、耗时、finish reason 与传输尝试；
- 合并后的候选结果、验证结果和程序 Reflection。

Provider 请求轨迹同样保存完整请求和原始响应，但不会记录 API Key、Cookie 或密码。日志包含出生信息与命盘，应按个人数据管理。

## 离线验证

运行：

```bash
cd backend
PYTHONPATH=. python scripts/validate_no_rag_report_pipeline.py /path/to/output
```

脚本使用生产 Prompt、Context、Schema、Pipeline 和 Validator，对 12 个 Golden 命造生成离线模拟报告，并保存每例 Prompt、模型输出、验证结果、Markdown 报告和校准 token 估算。另注入一次确定性错误验证最小 JSON Patch 修复。
