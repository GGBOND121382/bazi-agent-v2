# Prompt Architecture V6：六亲、健康与全生命周期大运

## 1. 设计原则

V6 不另起一套松散 Prompt，而是在 V5 已有的专业分析骨架上扩展：

```text
确定性事实权威
→ 专业结构判断
→ RAG 分层证据
→ 主题化落地
→ Reflection
→ 事实/引用/安全验证
→ 局部修复
```

六亲、健康和大运均属于主分析契约中的必答维度，而不是可有可无的附加段落。

## 2. 六亲：星、宫、岁运三层联合

每一类六亲都要求沿同一推理链分析：

1. **六亲星**：结合性别映射对应十神，检查透干、藏干、根气、旺衰及制化；
2. **六亲宫**：结合年柱、月柱、日支、时柱等宫位信息，检查刑冲合害会；
3. **岁运触发**：说明大运、流年、流月如何引动相关星与宫位；
4. **关系结论**：区分命理结构、可能表现和现实建议，避免仅凭单一十神下结论。

必覆盖对象：父亲、母亲、兄弟姐妹、配偶/婚恋、子女和整体家庭互动。

## 3. 健康：体质底色、保护因素与触发阶段

健康分析沿用现有五行、月令、调候和岁运分析，不建立脱离命盘的医学判断：

1. **体质底色**：五行偏性、寒暖燥湿、气机与调候；
2. **传统象义**：脏腑和身体部位只作为传统命理对应解释；
3. **保护因素**：说明哪些五行、组合或岁运能缓解失衡；
4. **触发阶段**：区分原局长期倾向与某步大运、某年/月/日的阶段性变化；
5. **建议边界**：可以给出生活方式与检查提醒，但不得替代医学诊断。

这保证系统不会回避健康主题，也不会把命理倾向伪装成确定疾病。

## 4. 大运：完整生命周期而非只分析当前大运

模型输入包含确定性起运信息和完整大运表，输出必须覆盖：

1. 出生至起运阶段；
2. 起运节点；
3. 大运表中的每一柱，保持原始顺序；
4. 每柱的起止时间、年龄、干支十神、藏干及与原局关系；
5. 每柱的综合、事业、财运、感情、六亲和健康；
6. 前后大运之间的承接、转折和跨运趋势。

逐柱分析仍遵循现有主链：月令与日主 → 格局/喜忌 → 干支作用 → 主题落地，而不是只根据大运干支写通用文案。

## 5. 报告与问答共用专业契约

报告负责生成完整结构化矩阵；问答根据用户选择注入：

- 原局；
- 出生至起运；
- 指定大运；
- 完整大运表；
- 流年、流月、流日；
- 最近对话历史；
- 对应 RAG 资料。

因此用户可以追问某位六亲、某类健康倾向、某步大运，或比较多个阶段，而不会让模型自行猜测时间范围。

## 6. 可查看的“推理流程”

系统保存并展示的是可审计生成轨迹：

- 实际 Prompt；
- 确定性上下文；
- RAG 查询和命中；
- 模型显式 `reasoning_summary`；
- 原始结构化输出；
- Reflection；
- 验证错误；
- repair Prompt 与修复输出；
- 最终采用结果。

这是真实可复现的工程轨迹，不冒充模型服务未返回的内部隐藏思维链。
## 8. V6.1：岁运关系全部回归确定性上下文

V6.1 不再要求模型自行比较干支来识别伏吟、反吟、天克地冲或岁运并临。
`analysis_context.temporal.dayun_table[*].relations` 与问答的 `temporal_interactions` 由规则引擎预先给出：

- 完整天干五行相克方向；
- 每个岁运柱与原局年、月、日、时四柱的作用；
- 当前大运、流年、流月、流日之间的交叉作用；
- 岁运并临、严格伏吟、反吟候选和天克地冲；
- 跨时间层级组成的三合、三会和三刑。

Prompt 的职责由“检查并计算这些关系”调整为“读取并解释这些关系”。模型不得创造上下文中不存在的关系，
也不得把 `high_attention` 直接翻译成灾祸；必须继续结合旺衰、喜忌、格局、宫位、成化和救应条件。
