# 专业命理 Prompt 架构 v5

## 1. 目标

v5 将大模型职责限定为“解释确定性命盘与岁运事实”，不允许模型参与排盘或修改计算结果。完整分析由四层组成：

1. 确定性 `analysis_context`；
2. 子平结构优先的专业分析矩阵；
3. 可审计推理摘要；
4. Reflection 自检与修订。

## 2. 确定性上下文

`analysis_context` 是模型唯一命盘事实源，包含：

- 计算配置、规范化时间、引擎版本和警告；
- 四柱、日主、十神、藏干、十二长生、自坐、旬空、纳音；
- 月令、节气、人元司令和五行统计；
- 天干地支合会冲刑害破；
- 原局神煞及其柱位、规则和来源；
- 起运、大运表、预计算岁运；
- 查询场景下的当前大运、流年、十二流月和指定流日。

模型不得重新排盘、换柱或补算上述字段。旺衰、格局、喜用与应期属于解释层，必须区分于确定性事实。

## 3. 专业分析矩阵

分析必须覆盖：

1. 月令本中余气、人元司令与旺相休囚死；
2. 日主得令、得地、得势，根气、透干与克泄耗；
3. 藏干十神、透藏、虚浮、盖头、截脚、清杂与制化；
4. 寒暖燥湿、五行流通及调候、扶抑、病药、通关；
5. 天干五合相冲及地支合会冲刑害破，并核验成局和化气条件；
6. 格局候选、成格、破格、救应与特殊格局排除条件；
7. 用神、相神、喜神、忌神、仇神及其服务目标；
8. 纳音的辅助校验；
9. 神煞结合柱位、十神和喜用的喜忌；
10. 原局 → 大运 → 流年 → 流月 → 流日的逐层触发；
11. 性格、事业、财运、感情、人际和健康倾向的结构化落地。

## 4. 可审计推理摘要

系统不要求或保存模型的隐藏思维链。模型输出的是结构化摘要：

- `dimension`：分析维度；
- `conclusion`：阶段结论；
- `fact_ids`、`rule_ids`、`evidence_ids`：可追溯依据；
- `counterpoints`：反向因素；
- `confidence`：置信度。

## 5. Reflection

模型在提交结果前检查：

- 是否改写确定性事实；
- 专业维度是否完整；
- 强弱是否有正反证据；
- 格局是否说明成立、破格、救应和排除条件；
- 喜用是否避免“缺什么补什么”；
- 是否把见合误写成已化；
- 是否遵守岁运层级；
- 是否让神煞或纳音凌驾于月令和十神；
- 引用 ID 是否存在；
- 是否覆盖用户关注点并消除矛盾。

当 `reflection.status=revise` 或缺少 Reflection 时，编排器把候选分析和具体反馈送回模型修订，最多执行配置的修订次数。

## 6. RAG 配额

检索优先级为：

1. 用户关注主题；
2. 旺衰、藏干、调候、格局和喜用；
3. 干支关系；
4. 大运流年应期；
5. 限额后的神煞；
6. 纳音辅助资料。

神煞查询限制数量，避免挤占格局和喜用资料。`interpretation` 被视为综合任务，可召回经过审批的规则、格局和解释类语料。

## 7. 评估

`contracts/examples/professional_prompt_eval_cases.json` 提供：

- 100 分评分量表；
- `己卯 庚午 壬子 丙午` 与 `乙亥 戊子 丁亥 戊申` 回归范本；
- 必须覆盖的事实和分析维度；
- 禁止错误；
- 正反表达样例。
