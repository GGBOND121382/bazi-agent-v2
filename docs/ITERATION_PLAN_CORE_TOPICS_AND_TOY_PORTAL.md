# 核心命理能力与玩具门户迭代计划

## 目标

本轮把六亲、健康和完整大运提升为报告与问答的核心能力，同时用尽可能轻量的方式补齐登录、用户隔离、admin 管理、对话历史和持久化日志。

## 实施顺序

### 阶段 A：核心分析契约

1. 保留现有“确定性排盘事实 → RAG → 结构化模型输出 → Reflection → 验证/修复”的主链。
2. 在同一专业分析 Prompt 中加入三套必填矩阵：
   - 六亲矩阵；
   - 健康矩阵；
   - 出生至起运及逐柱大运矩阵。
3. 扩充结构化分析 DTO 和报告章节，避免核心内容只出现在自由文本中。
4. 将同一套确定性事实和专业约束复用于问答 Prompt。

### 阶段 B：完整大运交互

1. 将确定性大运表完整传入报告分析。
2. 报告增加出生至起运、逐柱大运和跨运承接总结。
3. 对话支持选择某一步大运、出生至起运或全生命周期。
4. 保存每个问答线程，允许恢复和继续提问。

### 阶段 C：生成过程审计

1. 记录实际 system prompt、输入上下文、RAG 查询与命中资料。
2. 记录模型原始输出、Reflection、验证错误、修复 Prompt 和最终输出。
3. 报告和问答页面复用现有参考资料交互，增加“生成过程”查看入口。
4. 不声称展示模型不可访问的隐藏思维链，只展示系统真实保存的显式生成轨迹。

### 阶段 D：玩具级门户和持久化

1. 单 SQLite 文件保存用户、命盘、报告、问答线程、消息和模型调用记录。
2. 简单 Cookie Session；角色仅分 admin 和 user。
3. admin 页面支持创建用户、重置密码、查看用户命盘和对话。
4. 初始密码由 `config.local.env` 配置。
5. 应用日志、错误日志和 LLM 调用日志写入 `runtime/logs/`，重启后保留。

### 阶段 E：验收

1. 后端测试、Ruff、mypy strict。
2. 前端单测、类型检查、构建和 ESLint。
3. 重启持久化冒烟测试。
4. README 写明数据库、日志、初始用户和重置方式。

## 本轮明确不做

- PostgreSQL、Redis、Celery 或分布式任务恢复；
- 邮件注册、验证码、找回密码；
- 复杂 RBAC 和生产级安全审计平台；
- 对象存储和正式 PDF 导出服务；
- 模型平台不可返回的隐藏思维链展示。
